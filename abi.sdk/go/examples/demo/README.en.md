# ABI Go Server SDK Interactive Demo

**语言 / Language / 言語**: [简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

This directory contains the two-step interactive demonstration program [`main.go`](./main.go) for the **ABI Go Server SDK (`github.com/anylink/abi-go-sdk`)** (implemented with the pure Go standard library and zero third-party dependencies).

To help developers inspect the exact wire protocol payload generated by the SDK without being overwhelmed by verbose logs, the Demo adopts a **"1. Configure Parameters & Preview Request JSON (`POST /collect/api/v1/track/batch`) -> 2. Confirm to Submit & Print Response JSON"** workflow:

1. **Step 1 (Stage & Preview)**: Uses `abi.NewStagingConsumer` to merge static/dynamic super properties, validate identifiers, and protect 64-bit Snowflake IDs exceeding $2^{53}-1$ in memory, printing a single formatted request JSON preview (**zero network side effects**).
2. **Step 2 (Confirm & Submit)**:
   - In an interactive terminal (TTY) without `--yes`, prompts the developer to enter `y` to confirm submission (any other key cancels immediately without sending a request);
   - When `--yes` is passed or when running in a non-interactive pipe/CI environment (non-TTY), automatically submits the batch and prints a single gateway **`Response JSON`**.

---

## 1. Quick Start

Ensure **Go 1.22+** is installed locally.

### Option 1: Interactive Request JSON Preview & Confirmation (Default Order Scenario)

Run directly in a terminal. The program first prints the complete `POST /collect/api/v1/track/batch` request JSON, and after you enter `y`, submits it via an embedded local mock gateway:

```bash
cd abi.sdk/go
go run ./examples/demo
```

### Option 2: Non-Interactive One-Command Submission (Automated Testing / Fast Debugging)

Pass `--yes` to skip the interactive confirmation prompt and sequentially output the **Request JSON Preview** and **Response JSON**:

```bash
cd abi.sdk/go
go run ./examples/demo --yes
```

### Option 3: Customize Super Properties & Scenario Against a Live ABI Ingest Gateway (`:8081`)

When a local or staging `abi.srv` Ingest Gateway (listening on `:8081` by default) is running, customize project credentials, business scenarios, and super properties before previewing and submitting:

```bash
cd abi.sdk/go
go run ./examples/demo \
  --server-url="http://127.0.0.1:8081" \
  --project-id=1 \
  --token="abi_tok_demo_go" \
  --scenario="all" \
  --super-props='{"$app_version":"2.6.0","$platform":"GoServer","service_name":"checkout-api"}' \
  --dynamic-super=true \
  --dry-run=true
```

## 2. CLI Flags Reference

| Flag | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--server-url` | `string` | `""` (empty) | Base URL of the ABI Ingest Gateway (e.g. `http://127.0.0.1:8081`). When empty, starts an on-demand embedded local mock gateway (`127.0.0.1:0`) only during the **confirm submission stage**. |
| `--project-id` | `int64` | `1` | Target ABI Project ID (maps to request body `project_id`). |
| `--token` | `string` | `"abi_tok_demo_go"` | ABI project write token (maps to request body `project_token`). |
| `--scenario` | `string` | `"order"` | Demo scenario to generate: `browse` \| `identity` \| `order` \| `profile` \| `all`. |
| `--super-props` | `string` | `'{"$app_version":"2.5.0","$platform":"GoServer","service_name":"order-service"}'` | Static super properties JSON string (pass `'{}'` to disable static super properties). |
| `--dynamic-super` | `bool` | `true` | Whether to register a dynamic super properties callback (injects `server_region` and real-time `goroutine_count` into behavioral events). |
| `--dry-run` | `bool` | `false` | Whether to include `"dry_run": true` in the request payload (gateway performs full validation without writing to Kafka / StarRocks). |
| `--yes` | `bool` | `false` | Non-interactive auto-confirm submission; when `--yes=false` and stdin is an interactive TTY, waits for `y` confirmation. |

### Available `--scenario` Options

- `order` (**Default**): Full order lifecycle events (`TrackWithOptions` deterministic idempotency key walkthrough; *Note: per D7① / G6 gate, `TrackFirst` / `TrackUpdate` / `TrackOverwrite` are marked unsupported in current version*) and automatic string serialization for 64-bit Snowflake IDs exceeding $2^{53}-1$.
- `browse`: Visitor browsing before login (with visitor `distinct_id` only: `$pageview` and `ProductViewed`).
- `identity`: User signup & login automatic dual-ID binding (`$signup` + `$login` carrying both `login_id` and visitor `distinct_id`, automatically bound by Flink).
- `profile`: All 7 `$user_*` user profile operations (automatically isolates static/dynamic super properties to prevent behavioral fields from polluting the user profile table).
- `all`: Sequentially combines all 4 scenarios above into a single batch request payload.

## 3. Programmatic Two-Step Usage (Preview JSON First, Confirm Before Sending)

Application code or debugging tools can directly call `BuildDemoRequestPreview` and `ConfirmSubmitDemo` exposed in [`main.go`](./main.go), or use `abi.NewStagingConsumer` provided by the SDK:

```go
package main

import (
	"fmt"
	"log"

	abi "github.com/anylink/abi-go-sdk"
)

func previewThenSubmitExample() {
	// Step 1: Initialize in-memory StagingConsumer (dryRun=false), configure super properties, and record events
	staging := abi.NewStagingConsumer(1, "abi_tok_demo_go", false)
	sdk := abi.New(staging)

	_ = sdk.SetSuperProperties(map[string]any{
		"$app_version": "2.5.0",
		"$platform":    "GoServer",
		"service_name": "order-service",
	})
	_ = sdk.Track("acct_900102", "vis_dev_7f8e9a01", "OrderPaid", map[string]any{
		"order_no":     "ORD-20261110-8801",
		"snowflake_id": int64(9007199254740999), // > 2^53-1, automatically serialized as "9007199254740999" in preview JSON
		"amount":       2549.15,
	})

	// Inspect the formatted JSON payload to be sent to POST /collect/api/v1/track/batch (no network request made yet)
	reqJSON, err := staging.PreviewRequestJSON()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("Request JSON Preview:\n", reqJSON)

	// Step 2: Confirm and submit to the gateway to receive the response envelope (or forward via staging.ConfirmSubmit(batchConsumer))
	respEnv, err := staging.SubmitToGateway(abi.BatchConfig{
		ServerURL:    "http://127.0.0.1:8081",
		CompressGzip: true,
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("Gateway accepted=%d, rejected=%d, request_id=%s\n",
		respEnv.Data.Accepted, respEnv.Data.Rejected, respEnv.RequestID)
}
```

> **Tip**: If you want to modify super properties and regenerate the payload after previewing, call `staging.Reset()` to clear the staged queue, update `sdk.SetSuperProperties(...)`, record events again, and call `staging.PreviewRequestJSON()`.

## 4. High-Throughput Asynchronous Production Integration

In high-concurrency production microservices, once payload preview and integration verification are complete, initialize a singleton asynchronous `*abi.BatchConsumer` at process startup (supporting Gzip compression, dual batch-size/interval triggers, and idempotent 429/5xx retries), and call `analytics.Close()` before process exit to flush all buffered events:

```go
consumer, err := abi.NewBatchConsumer(abi.BatchConfig{
	ServerURL:     "http://127.0.0.1:8081",
	ProjectID:     1,
	ProjectToken:  "abi_tok_demo_go",
	BatchSize:     100,
	FlushInterval: 2 * time.Second,
	CompressGzip:  true,
})
if err != nil {
	log.Fatal(err)
}
analytics := abi.New(consumer)
defer analytics.Close()
```
